# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

EQdyna.2Dcycle is a 2D FEM code for simulating physics-based multicycle earthquake dynamics on geometrically complex fault systems: Fortran 90 core (`src/`), Python case management and post-processing scripts, and test suites with reference results.

## Build and Installation

```bash
./install.sh -e macos     # macOS: sets up environment and builds
./install.sh -m ubuntu    # Ubuntu/Linux
./install.sh -m macos     # just build, assumes dependencies exist
source install.sh         # source only, to set env vars (sets EQDYNA2DCYCLEROOT, adds bin/ and scripts/ to PATH)
```

Manual build:
```bash
cd src/ && make    # produces run_eqdyna2d_<VERSION> using the top-level VERSION file
cd .. && mkdir -p bin && cp src/run_eqdyna2d_* bin/
```
The root `VERSION` file (single-line, e.g. `2.0.3`) is read by `src/makefile`;
the binary is named `run_eqdyna2d_$(VERSION)`. Bump the version there and
rebuild to produce a new binary alongside old ones.

## Running Simulations

```bash
create.newcase --work_dir work/my_case --compset paper.saf.A          # named flags (preferred)
create.newcase work/my_case paper.saf.A                                # legacy positional still works
create.newcase --list                                                  # list available compsets
create.newcase --work_dir work/my_case --compset paper.saf.A --force   # overwrite existing

cd work/my_case
# edit user_defined_params.py if needed
python3 case.setup   # writes FE_*.txt + run.sh from user_defined_params.py
python3 meshgen.py   # C_mesh=3 (gmsh) cases only: produces fem_mesh_output/ and nsmpGeoPhys.txt
bash run.sh          # launches the simulation in background via nohup
```

`create.newcase` fails by default if the destination exists; `--force` wipes
and recreates. It copies `compset/<name>/*`, `scripts/*`, and `bin/*` into
the case dir (skipping generated files like FE_*.txt and run.sh).

`run.sh` exports `GFORTRAN_UNBUFFERED_ALL=1` (flushes Fortran stdout
immediately for real-time log tailing) and
`OMP_NUM_THREADS=${OMP_NUM_THREADS:-1}` (default serial, overridable in the
caller's env). Output goes to a timestamped `run_YYYYMMDD_HHMMSS.log`; raw
results (`totalop.txt*`, `cyclelog.txt*`, `interval.txt*`, `binaryop`) move
to `aRawSimuData/` after the binary exits.

## Testing

```bash
python3 -m test_system.test_all         # complete pipeline: compile, create case, mesh, run, post-process, verify against reference results
python3 test_system/verify.test.py      # manual verification against reference data only
```

## Key File Types and Architecture

### Core Fortran Source (`src/`)
`eqdyna2d.f90` main program entry; `globalvar.f90` global variables/data
structures; `driver.f90` main simulation driver; `faulting.f90`/`fric.f90`
fault mechanics and friction laws; `meshgen.f90`/`meshgen1.f90` mesh
generation; `qdct*.f90` finite element routines (2D/3D quad elements);
`contm*.f90` contact mechanics; `interstress.f90` interseismic stress
calculations.

### Case Configuration
Full details (contents, figures, generation scripts) live in each compset's own README; the lines below give only the facts not restated there.
- `compset/paper.saf.A/`: Liu et al. (2022) Model A, C_mesh=2. Uses the smooth per-node `Rate_direction.txt` recovered from the paper-era local archive.
- `compset/saf.gmsh.lite/`: paper-A reproduction, C_mesh=3, coarser dxy=400m. First cycle: 473 yr / M5.7 (paper-A: 471 yr / M5.74).
- `compset/subei.gmsh.lite/`: Subei fault system (atf, dxs, sbt), C_mesh=3, uses uniform-x loading (`uniformXLoadingAngle`, no paper `Rate_direction.txt` exists for it); multi-surface decomposition for the connected junctions.
- `compset/xianshuihe.gmsh.lite/`: Xianshuihe fault (鲜水河断裂), eastern Tibet, C_mesh=3, **runnable**. 7 faults (`MERGE_GROUPS = [[1,2],[0,4],[3],[5],[6],[7],[8]]`, 482.7 km total). Per-node loading from GSRM v2.1; use **TARGET = 90–100 MPa** not the SAF's 120 — compression angle here straddles zero (43% positive vs 91% for the SAF), so T/N > 1 drives nodes tensile. Reference: Qiao et al. (2022, EPSL 596, 117799).
- `compset/gulang.gmsh.lite/`: Gulang fault system (ft1..ft5, left-strike vertical), C_mesh=3, uniform-x loading. ftVis tuned to 5e21 Pa·s (1e21 too low for nucleation, 8.4e21 gives tensile normal at large strikes). `preprocess_control_points.py` resamples the raw 412-point `.gmt` digitisation (median ~30 m spacing) to a SAF-like 39-point set at ≥3 km arc-length spacing; originals kept as `*.gmt.txt.orig`.
- `user_defined_params.py`: Simulation parameters (inherits from defaultParameters.py)
- `userDefinedFaultSysGeoPhys.py`: Fault geometry and physics
- `FE_*.txt`: Input files generated by case.setup
- For the C_mesh=2 `Rate_direction.txt` file format, units, and how it
  feeds into paper eqs (1)-(3), see `compset/paper.saf.A/RATE_DIRECTION.md`.

### Python Utilities (`scripts/`)
- `case.setup`: Generates FE_*.txt + run.sh from user_defined_params.py
- `create.newcase`: New case from a compset (`--work_dir`, `--compset`, `--force`, `--list`; legacy positional form still accepted)
- `plotRuptureDynamics`: per-cycle 4-panel shear/normal/slip/rupture-time plot from totalop.txt. `MIN_PLOT_MAGNITUDE` env var (default 6.5) gates which cycles are saved as PNGs; `FORCE_REPLOT=1` re-renders existing plots; `CATALOG=1` runs catalog-only (no figures, ~10x faster), writing `aPlots/catalog.csv` (eqId, magnitude, moment, nucleation x/y, rupture duration, peak slip per cycle)
- `plot_event_slips_overtime_fig4.py`: Figure-4-style slip-distribution stacks; default tstart auto-populates 0, D, 2D, … over the total simulated kyr (window D = 3 kyr default)
- `plot_saf_figure3.py`: Figure-3-style long-term slip-rate comparisons
- `compare_cycle_over_strike.py`: overlay a chosen cycle's stress/slip/rupture-time curves from multiple cases plus the Pangaea reference
- `analyze_catalog.py`: reads `aPlots/catalog.csv`; computes b-value (LSQ on a user-windowed magnitude range; characteristic-fault MFDs need `--mmax 7.0` to exclude the bump), MFD, magnitude-vs-cycle, nucleation-vs-cycle; saves `aPlots/catalog_analysis.png`
- `monitor_runs.sh`: periodic status + Figure 4 + rupture-dynamics re-plot for active `paper.saf.A.*` and `saflite` cases; 600s default poll, override via first arg
- `plot_saf_figure6.py`: Figure-6-style cumulative moment release, magnitude histogram, magnitudes >6.6 against the Scharer & Yule (2020) datasets
- `plot_saf_figure9.py`: Figure-9-style characteristic-event slip distributions, selected by **rupture footprint** not cycle id (the published MATLAB's hard-coded ids mean nothing in another sequence). `--published` restores the paper's exact panels; `--cycles` takes an explicit list
- `paleo_site_stats.py`: Table-2-style recurrence-interval/slip statistics at the BF/FM/WW paleoseismic sites; parity-gated on the published MATLAB against the published Pangaea output
- `make_paper_figures.py`: one command for the full paper figure set — `python3 make_paper_figures.py <case_dir>`; stages catalog, figure3/4/5/6/9, analysis, rupture. `--skip rupture` for the cheap summary set, `--only <stages>`, `--list`; each stage logs to `aPlots/logs/<stage>.log`, the expensive per-cycle stage runs last
- `fetch_published_reference.sh`: fetches the published Zenodo software (10.5281/zenodo.5823021) and Pangaea results (10.1594/PANGAEA.940262) by DOI with md5 pinning, instead of vendoring 615 MB of immutable data
- `saf_result_utils.py`: loader helpers used by the plot_saf_* scripts
- `meshGenLib.py`: mesh generation utilities (C_mesh=3)
- `defaultParameters.py`: default simulation parameters

### Output Files
`totalop.txt*` main output (stress, slip, rupture time); `cyclelog.txt*`
earthquake cycle logging; `interval.txt*` inter-event intervals;
`aRawSimuData/` raw simulation results; `aPlots/` generated plots/figures.

## C_mesh Branching Architecture

The `C_mesh` parameter in `user_defined_params.py` controls the mesh and loading workflow:

| | C_mesh=2 (internal Fortran mesh) | C_mesh=3 (gmsh) |
|---|---|---|
| Mesh generator | `meshgen1.f90`, from `x*_1.txt` geometry files | `meshgen.py`, outputs to `fem_mesh_output/` |
| Loading file | `Rate_direction.txt`: `maxftnode × ntotft` rows, 2 cols — (1) loading rate s⁻¹, (2) angle between loading and fault tangent, deg | `nsmpGeoPhys.txt`: `maxftnode × ntotft` rows, 9 cols — (1) `tx`, (2) `ty` fault unit tangent, (3) `len` segment length m, (4) `ftType` (1 left-strike, -1 right-strike, 2 thrust, -2 normal), (5) `ftDip` deg (90=strike-slip), (6) `ftLoadMaxShear` far-field shear strain rate s⁻¹ (typically 1.427e-14), (7) `ftLoadAngle` deg (-999=auto), (8) `ftLoadWt` loading weight (default 450), (9) `ftVis` viscosity Pa·s (typically 6e21) |
| Where the loading file lives | `compset/<case>/comp_input/`, copied by `case.setup` | written by `meshgen.py` via `meshGenLib.py` |
| Reference case(s) | `compset/paper.saf.A/` | `compset/saf.gmsh.lite/`, `compset/subei.gmsh.lite/`, `compset/gulang.gmsh.lite/` |

**ftLoadWt / ftLoadAngle (C_mesh=3):** from `strbld.f90`, `ant = ftVis * 450 /
ftLoadWt`, `rs = ftLoadMaxShear / 450 * ftLoadWt * cos(2θ) * ant` — ftLoadWt
cancels in steady state and only sets the approach timescale (e.g.
`ftLoadWt = 0.8 * 450` for 80% loading, `0.1 * 450` for 10%). `ftLoadAngle =
-999` auto-computes `θ = atan(ty/tx)` (fault tangent from x-axis, assuming
tectonic loading along the general strike direction), clamped to 45° max
before computing shear/normal loading components.

### Source directories
`src/` — single development baseline (v2.0.3 code path; both C_mesh=2 and
C_mesh=3 branches). `archive/src.v2.1.0/` — archived v2.1.0 (gmsh-only
branch). `archive/published/source_local_recovered/code/` — preserved
paper-era v2.0.2 snapshot; **never published and not in a clone**, its
findings are written up in `compset/paper.saf.A/PROVENANCE.md` (`archive/` is
untracked).

### Interseismic viscosity (C_mesh=2, `interstress.f90`)
Per-node viscosity varies inversely with local loading rate (Liu et al. 2022 / Duan & Oglesby 2005):
```
ant_i = ant0 * str / rd(1,i)    (rd in rad/s, str in rad/s from FE_Global line 23)
rs_i  =  rd(1,i) * cos(2θ) * ant_i     → simplifies to str * cos(2θ) * ant0
rn_i  = -rd(1,i) * sin(2θ) * ant_i
```
At the fault node with peak `rd(1)`, `ant` hits its minimum `η_min = ant0 * str / rd_max`, which the paper reports in Table 1 (Model A: 7.0×10²¹ Pa·s with ant0=8.4e21 and rd_max≈540 nrad/yr). Fallback `ant = ant0` for nodes with `rd(1)=0` (fault endpoints).

### Performance notes (driver hot loop)
`alhs_inv = 1/alhs` is precomputed once after `qdct2` (in `eqdyna2d.f90`);
the driver's whole-array `brhs = brhs * alhs_inv` vectorizes to AVX2
`vmulpd`, avoiding per-timestep divisions. `qdct3.f90` skips the `zeroal`
check since `rdampm(1)=0` is enforced in `eqdyna2d.f90`; `formma` is always
false. OpenMP-parallelized: `qdct3` (`$OMP ATOMIC` on brhs assembly),
`hrglss` (same pattern), the velocity/displacement update in `driver.f90`,
and the `brhs = brhs*alhs_inv` multiply — thread count via `OMP_NUM_THREADS`
in run.sh, scaling ~2.8–3x on 4 threads (qdct3 limited by atomic
contention, hrglss near-linear). Per-op timing (`t_vd`, `t_qdct3`,
`t_hrglss`, `t_faulting`, `t_brhs`) prints every `print_every` timesteps
(default 300 = every 3 simulated seconds) with a date/time stamp.

### Magnitude convention (important when comparing to the paper)
`plotRuptureDynamics` computes moment with the model's own constants,
`mu = rou*vs^2 = 2670*3464^2 = 3.204e10 Pa` at 22 km seismogenic depth; the
paper's Figures 6 and 9 use `mu = 3500^2*3000 = 3.675e10 Pa` at the same
depth, so every magnitude/b-value in `catalog.csv` sits 0.04 Mw below the
paper's scale. `plot_saf_figure6.py`/`plot_saf_figure9.py` use the paper's
constants and are therefore NOT comparable to `catalog.csv` directly. The
paper's own constant is inconsistent with its model parameters (rou=2670,
vs=3464); making it selectable is planned.

### Output files
`meshGeneralInfo.txt` mesh summary (always written; replaces
`Mesh_general_info.txt`); `nsmpTanLen.txt` same content as `nsmpnv.txt`
(fault tangent + segment lengths); `totalop.txt{icstart}` all cycles
stacked (ncycles × totftnode rows, 5 cols/node). Fortran unit 6 = stdout;
output file uses unit 61 to avoid stdout conflict.

## Code Architecture

Workflow: case setup → input generation (`case.setup`) → mesh generation →
fault loading → dynamic rupture → post-processing (already detailed above
under Running Simulations and the C_mesh table). Friction model is chosen
via the `friclaw` parameter. Parameters flow `defaultParameters.py` →
`user_defined_params.py` → `case.setup` → FE_*.txt; the `par` object holds
all of them (mesh resolution, friction coefficients, material properties,
fault geometry).

## Dependencies
- **Fortran**: gfortran compiler
- **Python 3**: numpy, matplotlib, xarray
- **Optional**: gmsh, meshio, nbconvert (for advanced meshing)
